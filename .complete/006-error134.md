# Investigate and Resolve Error 134 During Data Generation

## Description
Every sequence seems to fail at the end of completion with exit code 134 (`SIGABRT`). This specifically manifests as a `terminate called without an active exception` error during the cleanup phase (e.g., when destroying actors and sensors). Investigate this error and determine a robust solution to ensure the data generation pipeline exits cleanly and can run continuous batches without crashing.

## Acceptance Criteria
- [x] Scripts (e.g., `loadingAttributesWeather.py`, `manualSpawning.py`) exit cleanly without throwing exit code 134.
- [x] No `terminate called without an active exception` messages are present in the generation logs.
- [x] All spawned actors (vehicles, pedestrians) and sensors (cameras) are properly destroyed in the simulator before the script terminates.
- [x] The generation pipeline continuously proceeds to the next sequence or configuration without being interrupted by simulator/client desync crashes.
- [x] For a given run of the `generateRun` script, the world is consistent between generated perspectives and angles (e.g., vehicles and people should be in the exact same places).

## Technical Tasks
1. **Trace Cleanup Logic**: Inspect the actor and sensor destruction sequence at the end of the data generation scripts (specifically, look around the "Destroying actors and sensors..." print statements).
2. **Identify Race Conditions**: Check if the script is exiting, disconnecting the CARLA Python client, or garbage-collecting Python objects before the asynchronous `destroy()` commands have been fully processed by the UE4 CARLA server.
3. **Implement Robust Teardown**: Wrap the teardown and destruction logic in robust `try-except-finally` blocks to guarantee execution.
4. **Synchronous Destruction Update**: Ensure that the simulator has finished destroying entities. Consider using `client.apply_batch_sync(...)` for bulk destruction or ensuring the CARLA world ticks after deletion commands are sent so they are finalized before disconnection.
5. **Testing & Validation**: Run a short pipeline sequence with multiple generation scripts sequentially to confirm exit code 134 no longer occurs and resources are correctly freed between runs.
